# 广小联 AI 全流程实战落地工作坊 · 参考实现（讲师用）

配套 [`gld_arch_coding`](https://github.com/xjtai/gld_arch_coding) 的一套填好的 SDD 文档，题目是《广小联企业级高可用智能客服 Agent》。

## ⚠️ 课上不要发给学员

学员仓库的 `prd.md` 写着：

> 「PRD → 需求理解 → 方案设计 → 实现」这条推导链，正是本次实战要考察的能力，**提前把设计给出来，练习就失去了意义**。

这套文档就是"提前给出来的设计"。3 小时倒计时下，学员拿到它必然照抄，而被跳过的恰恰是最值钱的三处：`spec.md` §2 消歧的思考、`plan.md` §6 不改清单的判断、`learnings.md` 里真实发生过的评审纠错。

**建议用法**：课上讲师自用（评审各组产出时心里有基准、某组卡死时给一段提示）；**课程结束后**再公开给学员对照复盘。

## 这是一种合格解，不是标准答案

SDD 里很多决策本来就有多个合理解。这套文档做的选择——

| 决策点 | 本方案的选择 | 其他合格选择 |
|---|---|---|
| 多智能体框架 | 自研 Router + Function Calling | Spring AI / LangGraph / AutoGen 都行 |
| 路由方式 | LLM 单次分类 | 规则匹配、或规则+LLM 混合 |
| 闲聊类 | 做（当兜底出口） | 不做，统一走"转人工"话术 |
| 售前/售后具体场景 | 各选 3 个 | 换成脑图里其他叶子节点同样成立 |
| 前端 | Flask + SSE 三栏页面 | 命令行 Demo 也满足验收 |

**评审各组时请只卡 `prd.md` §4 那五条验收标准**，别拿本方案的选型当尺子——否则会把"自己推导"训练成"猜讲师想要什么"。

哪些是真·硬要求，文档里都标了 `【硬要求】`。

## 怎么读最有价值

**别只看最终形态，重点看四份文档末尾的「变更记录」。** 那里记着 Coding Agent 起草后、人评审时纠了什么错、补了什么漏——这才是这套流程真正在训练的东西。`learnings.md` 的五条经验全部由这些记录推导而来，可以顺着倒推回去看。

几条串起来的线索，讲课时可以直接用：

- Agent 起草 `spec.md` 时把「退货」和「退款」当成了一件事 → 评审拆开 → 成为 `learnings.md` L-01
- Agent 选了 LangGraph，人以"3 小时学不完"否决 → `plan.md` §2 保留了被否决方案 → L-02
- `eval.md` 首轮实测准确率只有 80%，未达 85% 门槛 → 定位到隐含意图类失败 → 修复后 90% → L-04
